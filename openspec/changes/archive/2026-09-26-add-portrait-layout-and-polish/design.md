# Design: add-portrait-layout-and-polish

## Context

Три UX-правки: портретный режим, тултипы, живой огонь. Базовая архитектура (единый Pixi-канвас, дизайн-координаты) сохраняется.

## Decisions

1. **Два дизайн-разрешения.** `computeLayout(vw, vh)` выбирает режим (портрет: высота > ширины × 1.08) и пересчитывает DESIGN_W/H (1080×1920), REELS_AREA, CELL, BOTTOM_BAR. Все модули читают значения при создании.
2. **Смена режима = пересоздание Game.** Проще и надёжнее релайаута живых объектов: `main.ts` отслеживает смену режима и вызывает `createGame` заново; ассеты в кэше Assets (мгновенно), состояние — в localStorage (persist после каждого спина). `Game.destroy` корректно снимает тикер и слушатели окна.
3. **Портретные позиции Ui** — ветвление в конструкторе по MODE (пересоздание делает их актуальными). Панель paytable масштабируется по ширине экрана.
4. **Тултипы** — один переиспользуемый контейнер в Ui (eventMode none, поверх кнопок), позиция: над кнопкой, для верхней трети экрана — под; clamp по краям.
5. **Огонь** — два слоя в Embers: мерцающие ореолы в фиксированных точках свечей (наложение синусоид + scale-дыхание) и тлеющие искры (уже были).

## Risks / Trade-offs

- Пересоздание при повороте прерывает текущий спин — осознанный компромисс (баланс консистентен: ставка/выигрыш пишутся сразу).
- Позиции огней захардкожены под ландшафтный фон; в портрете часть ореолов уходит за кроп — искры и центральные ореолы остаются видимыми.
